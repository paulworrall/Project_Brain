# Project Brain — Codebase Summary

## Architecture Overview
Next.js 16 (App Router, TypeScript, Turbopack) with Tailwind CSS v4, Prisma 7 (Postgres/Neon, driver-adapter-based), and NextAuth v5 (beta) for email/password auth. All Level 1 MVP scope (Stages 1-5, Knowledge Upload, Chatbot, polish/QA/deploy) is complete, plus a long tail of post-MVP additions: a Phase-grouped Stage Tracker (`src/lib/phases.ts`), full Client/Workstream taxonomy navigation + global search, Phase 1 as a progressively-disclosed fluid workspace, commercial document management generalized into one shared "document has many Versions, exactly one current" pattern (MSA, Rate Cards, SOW Template Library), a Client-page "library" read-list UX for all three, an end-of-Phase-1 "Capabilities & Estimate Brief" panel, and the full "Build The Estimate" feature (Stage 6) — now through two build passes: the original feature build, then a substantial redesign (this session) driven directly by the user's own hands-on testing. Phase 3 (Stages 8-9) still renders Stage 8's real SOW-Template-selection panel; Stage 9/10 remain inert placeholders.

**Build The Estimate, current shape**: a PM opens "+ New estimate" (a modal that runs the *entire* build flow — create, add roles, review, save, download — without ever navigating to a page) or the estimate's own standalone page. Adding a role is a single step: paste or upload raw text, submit, and extraction + rate-card matching run automatically in the same request — there is no capability picker and no separate "Analyze/Re-analyze" step. Each extracted role is classified into one of the 12 fixed MAP capabilities *by the AI itself* (not chosen by the human up front); the review grid is one flat table with Capability as an ordinary first column, an inline "Update" control per row for correcting an already-resolved role's quantity, and Word + Excel downloads for the latest saved version shown at the top of the workspace.

## Toolchain Notes (this machine)
- **DB-touching Prisma CLI commands require WSL** on this machine (unsigned native binary blocked by endpoint security). **`prisma migrate dev --create-only` refuses non-interactively for any migration Prisma flags as unsafe** (e.g. adding a required column to a table with existing rows) — for a staged migration, hand-write the migration folder + `migration.sql` directly (matching the existing `YYYYMMDDHHMMSS_name` convention) instead of relying on `--create-only` to generate the stub, then apply with a normal `prisma migrate dev` via WSL. After any WSL-side `npm install`, immediately run `npm install` again from native Windows.
- **Real user data lives in this shared dev DB — check before assuming a table is empty.** A migration this session hit `RoleResolution` rows the user had created via their own manual testing (their "Test 5" estimate); the staged nullable→backfill→required migration handled it correctly, but a naive one-shot required-column migration would have failed outright. Always verify row counts before writing a migration, not just before running it.
- **Prisma `Decimal` instances are not JSON-serializable across the Server→Client Component boundary.** Convert to `Number`/string in the Server Component first.
- **`useFallbackStageProgress`'s second argument must be a stable array reference.**
- **`react-hooks/set-state-in-effect` (ESLint)**: do state updates inside the action function itself, not a `useEffect` watching `pending`.
- **serverExternalPackages**: `officeparser` must stay listed in `next.config.ts`.
- **A new npm dependency's transitive deps can carry their own CVEs** — `exceljs` pinned a `uuid` version with a moderate advisory; fixed via an `overrides` entry (same pattern as the earlier `pdfjs-dist` fix) rather than downgrading the package itself. Always run `npm audit` after adding a dependency, not just at random.
- **A library's bundled TS types can lag behind this project's `@types/node`** — `exceljs`'s `Buffer` parameter type didn't structurally match this project's newer `Buffer` (missing `resizable`/`detached`/etc.); no safe cast chain satisfied it, so an explicit `as any` (with an eslint-disable comment explaining why) was the pragmatic fix at that one call site, in a test file only.
