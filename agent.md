# Project Brain — Codebase Summary

## Architecture Overview
Next.js 16 (App Router, TypeScript, Turbopack) with Tailwind CSS v4, Prisma 7 (Postgres/Neon, driver-adapter-based), and NextAuth v5 (beta) for email/password auth. The full data schema is built, and all four agent pipelines (Intake, Clarification Extraction + Triage, Specialist Review Extraction, Chatbot) are live and verified end-to-end against the real Claude API and real Neon database — both locally and on the deployed production URL. The project page is a "workflow console": a Phase-grouped Stage Tracker (3 expandable Phase cards over the 10 underlying Stages, plus a separate Delivery Monitoring indicator for Stage 10 — presentation-layer only, `src/lib/phases.ts`; Stages remain the actual source of truth), then a numbered, expandable step list (all 10 pipeline stages) beside a sidebar stack of Cards — the chatbot, the ad-hoc knowledge-upload form + list, and the live Set-Up Checklist (the checklist also appears inline on Step 1). A separate Outputs Library page lists every Document the project has produced, and each links to a Version History page for that artifact. **All Level 1 MVP scope from the PRP is complete**: Stages 1-5 of the pipeline, the cross-cutting Knowledge Upload and Chatbot features, full polish/QA/deployment, and the Phase Presentation Layer rework of the Stage Tracker. Stage 6 is unlocked but not yet built; Stages 7-10 render as inert placeholders (Level 2/3, out of MVP scope).

- To change a production env var: `npx vercel env rm <NAME> production --scope map25 --yes` then pipe the new value into `npx vercel env add <NAME> production --scope map25` — never type secret values directly into a shell command that echoes them, and never `Read` `.env.local` as a whole file (it will display every value in full); use `grep`/`sed` on the specific line instead.
